# Governance

Created by Carlos Olivera Terrazas — Founder & Principal Architect.

Carlos owns the project's direction, architectural foundations, domain, and account administration. Agents perform engineering and operations within explicit authority, project scope, and budgets. Public issues and pull requests welcome contributions.

Trusted human collaborators have write access, without administration. They and
their agents have the same authority as any external contributor over sensitive
paths: collaborator reviews do not authorize those changes. Carlos remains the
only person who approves sensitive changes at the current PR head and merges.
On a personal-account repository, GitHub may not enforce the merge restriction;
it remains a project rule. See [collaborator guidance](CONTRIBUTING.md#collaborators-with-write-access).

Automated changes identify their actor, task, commit, checks, and deployment. The initial bootstrap used Carlos's authenticated GitHub account to publish commits authored by `Codex Bootstrap <agent@a2aviary.io>`. Publication now uses the repository-scoped a2aviary Operator App.

Changes to governance, licensing, authorization, workflows, infrastructure, credential handling, and the controls themselves require Carlos's approval of the current pull-request head. A trusted external policy check enforces this where activated. Labels, email receipt, instructions in submitted materials, and agent self-approval never grant authority.

Routine changes follow implementation, checks, pull request, trusted policy validation, merge, deployment, and public verification. Autonomous merging remains disabled until the operational identity and protection checks are verified.
